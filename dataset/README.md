# Matchlens open synthetic football dataset

Five complete 90-minute football matches generated by the Matchlens simulator: every event with pitch coordinates,
and 1 Hz positions and speeds for all 22 players and the ball. All clubs, players, venues and competitions are
fictional, so the data is free of rights restrictions.

| Match | Seed | Storyline | Final score | Events | Tracking frames |
|---|---|---|---|---|---|
| `ml-demo-001` | 7 | The Kestrel Park Comeback (scripted) | Northbridge 3-2 Harbour City | 1,591 | 5,743 |
| `ml-open-s001` | 1 | Unscripted | Northbridge 1-2 Harbour City | 1,743 | 5,704 |
| `ml-open-s002` | 2 | Unscripted | Northbridge 1-0 Harbour City | 1,818 | 5,769 |
| `ml-open-s003` | 3 | Unscripted | Northbridge 0-3 Harbour City | 1,732 | 5,739 |
| `ml-open-s004` | 4 | Unscripted | Northbridge 3-1 Harbour City | 1,752 | 5,845 |

`ml-demo-001` is the hero match of the live Matchlens demo, event for event: Harbour City lead 2-0 at half-time, a
red card and a high press turn the game, and the 64th-minute goal is first credited to the wrong player and then
corrected in the feed. The unscripted matches have no storyline beats; goals come from the simulator's xG model.

## Files

```text
dataset/
├── index.json                    every match with seed, storyline, final score and counts
└── <match_id>/
    ├── meta.json                 teams, lineups, players, venue, kick-off, seed, storyline, summary stats
    ├── events.jsonl              one event per line, in feed order
    └── tracking.jsonl.gz         one tracking frame per line (gzip), 1 Hz
```

Schemas (JSON Schema, draft 2020-12) and field-by-field documentation: [`docs/SCHEMA.md`](../docs/SCHEMA.md).

- Event: [`event.schema.json`](../docs/schema/event.schema.json)
- Tracking frame: [`tracking-frame.schema.json`](../docs/schema/tracking-frame.schema.json)
- Match metadata (`meta.json` → `meta`): [`match-meta.schema.json`](../docs/schema/match-meta.schema.json)
- Storyline (`meta.json` → `storyline`): [`storyline.schema.json`](../docs/schema/storyline.schema.json)

Pitch coordinates are metres on a 105 x 68 pitch, with the home team attacking towards `x = 105` in both halves.
`elapsed` is seconds since kick-off excluding the half-time break; `clock` is the broadcast clock. Speeds in tracking
frames are m/s.

## Event types

20 types: `kickoff`, `pass`, `carry`, `pressure`, `tackle`, `interception`, `possession_change`, `shot`, `save`,
`goal`, `foul`, `card`, `free_kick`, `corner`, `throw_in`, `goal_kick`, `substitution`, `half_time`, `full_time`
and `correction`. Passes carry ball speed, height and whether the passer was under pressure; shots carry xG, shot
speed, body part and distance. A `correction` amends an earlier event through `corrects_event_id` and must be
applied before computing statistics.

## Loading

Python, standard library only:

```python
import gzip, json

events = [json.loads(line) for line in open("dataset/ml-demo-001/events.jsonl")]
with gzip.open("dataset/ml-demo-001/tracking.jsonl.gz", "rt") as fh:
    frames = [json.loads(line) for line in fh]

passes = [e for e in events if e["type"] == "pass"]
print(len(passes), sum(e["outcome"] == "success" for e in passes) / len(passes))
```

pandas:

```python
import pandas as pd

events = pd.read_json("dataset/ml-demo-001/events.jsonl", lines=True)
tracking = pd.read_json("dataset/ml-demo-001/tracking.jsonl.gz", lines=True).explode("entities")
```

Inside the Matchlens backend, `matchlens.dataset.export.load_match(path)` returns the validated models, and a
match can be replayed through the live pipeline with `JsonLinesAdapter`.

## Calibration

The simulator is calibrated on real football (FR-008). The same 23 metrics were measured on 100 real men's
top-flight matches (English top flight, 2015/16, from StatsBomb Open Data) and on simulated matches, and the
simulator is tuned until every simulated average lies within one real match-to-match standard deviation of the real
average. Only aggregate statistics of the real matches are kept
([`reference_profile.json`](../backend/src/matchlens/simulator/reference_profile.json)): no real club, player,
competition or match names or data are in this dataset.

Mean over 20 unscripted matches (seeds 1 to 20) against the real average, both teams combined:

| Metric | Simulated | Real |
|---|---|---|
| Passes (throw-ins excluded) | 891 | 919 |
| Pass completion | 76.5% | 75.8% |
| Median pass length | 15.1 m | 15.2 m |
| Passes under 15 m / over 30 m | 49.4% / 18.6% | 49.1% / 16.9% |
| Completion of passes over 30 m | 46.8% | 47.9% |
| Passes under pressure / completed under pressure | 17.0% / 67.3% | 15.6% / 68.1% |
| Shots | 26.2 | 25.2 |
| Goals | 2.5 | 2.55 |
| Shots on target / blocked | 30.2% / 28.8% | 31.6% / 29.9% |
| xG per shot | 0.12 | 0.10 |
| Shot distance / from inside the box | 16.9 m / 64.6% | 16.7 m / 61.4% |
| Headed shots | 17.0% | 15.0% |
| Corners / throw-ins / goal kicks | 11.0 / 43.7 / 17.5 | 10.7 / 46.0 / 16.4 |
| Fouls / yellow cards | 28.1 / 3.3 | 25.3 / 3.5 |
| Tackles won / interceptions | 25.7 / 15.4 | 23.9 / 13.8 |
| Outfield distance per player | 10.2 km | 9.5-11.5 km (published range) |
| Top sprint speed | 33.2 km/h | 31-36 km/h (published range) |

Reproduce it with `cd backend && uv run python -m matchlens.simulator.calibration --matches 20`, and the real
profile with `uv run python -m matchlens.simulator.reference --matches 100`. Each match's own figures are in its
`meta.json` under `summary`; `index.json` records the real averages, spreads and metric definitions. The real data
has no tracking, so distance and speed are checked against rounded published ranges. xG comes from different models
(StatsBomb's and the simulator's), so it is a looser comparison.

Real-data calibration: [StatsBomb Open Data](https://github.com/statsbomb/open-data). Data provided by StatsBomb.

Known simplifications: the home team attacks the same way in both halves, tracking is 1 Hz, and there are no
offsides or injuries.

## Regenerating

The export is deterministic: the same seeds produce byte-identical files.

```bash
cd backend && uv run python -m matchlens.dataset.export --out ../dataset --schemas ../docs/schema
```

`--unscripted N` changes how many unscripted matches are written. A test checks that `ml-demo-001` still matches the
simulator, so a simulator change that alters the hero match fails the test suite until the dataset is regenerated.
